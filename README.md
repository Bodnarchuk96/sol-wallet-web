# SOL Wallet 10.1 — євро, гривня та захищений сімейний акаунт

Особистий вебзастосунок для розподілу грошей BMH і сім'ї. У цьому публічному репозиторії міститься **лише код застосунку**, без сімейних доходів, номерів карток, паролів чи приватних резервних копій.

## Як відкрити валютний гаманець на телефоні

1. Відкрий https://bodnarchuk96.github.io/sol-wallet-web/?wallets=1&v=11
2. Розблокуй гаманець своєю звичайною секретною фразою (нова не потрібна).
3. Натисни **«€₴ Валюти»** внизу екрана або **«Мої валюти: € / ₴»** на головному екрані.
4. Обери **BMH / Сім’я** і **EUR / UAH**. На екрані — чотири незалежні баланси.

## Як додати джерело надходження

1. У розділі «Валюти € / ₴» вибери потрібний бюджет і валюту.
2. Натисни **«＋ Джерело доходу»**.
3. Напиши назву — наприклад, «Оплата клієнта BMH», «Виплата з відеоплатформи», «Зарплата» або «Переказ з України». Це **лише приклади**, вони не створені як реальні надходження.
4. За бажанням вкажи частоту (разове, щомісячне, нерегулярне), очікувану суму та назву картки/рахунку.
5. Натисни «Зберегти операцію». Джерело буде доступне в меню «Надходження».

**Важливо:** очікувана сума лише для планування. Вона **не додається до балансу**.

## Як зарахувати фактичні гроші

1. Натисни **«＋ Надходження»** та вибери збережене джерело.
2. Вкажи суму, дату й картку/рахунок.
3. Переглянь автоматичний розподіл і підтверди запис.
4. Після цього сума буде зарахована **лише у вибраній валюті**.

## Облік валюти та безпека

- Старі записи у євро залишаються у EUR. Гривневі операції мають окрему історію й цілі.
- Конвертацію EUR↔UAH записуй лише за **фактичними** списаною та отриманою сумами (комісії враховуються в реальній сумі).
- Назви рахунків — ручний облік. Банки та платіжні платформи не підключені.
- Дані зберігаються зашифрованими у браузері; автоматичної синхронізації між пристроями ще немає.
- Перед заповненням справжніх сум зроби зашифровану резервну копію. Не зберігай пароль або незашифровану історію в публічному GitHub.
- Це фінансовий планувальник, не банківська система, німецька EÜR чи податкова декларація.


## Сімейний калькулятор 10.0

- Відкрий «🏠 Сімейний калькулятор» після розблокування; він працює у валютному сімейному гаманці, а не в BMH.
- Введи суму у швидкий розрахунок. Для надходження програма показує розподіл за наявними конвертами, для покупки — залишок і ризик перевищення ліміту. **Перегляд не додає і не списує гроші.**
- Підтверджені операції зберігай через «Записати надходження» / «Записати покупку». Повернення власних коштів обирай як тип сімейного надходження; початковий залишок — окремим типом, він не враховується у звіті як новий дохід.
- Якщо українська картка списала гривні за покупку з ціною у євро, запиши **фактичне списання UAH один раз**; EUR із чека лише довідка.
- Для зняття готівки через обмін UAH → EUR створи сімейний EUR-рахунок типу «Готівка» й зафіксуй дві фактичні суми в обміні; не записуй це ще раз як покупку. Якщо комісія не включена у фактичну суму обміну, запиши її окремою UAH-витратою типу «Банківська комісія».
- У «Сімейний калькулятор → Ліміти» встанови щомісячні ліміти за категоріями в кожній валюті. Без установленого ліміту програма не показує вигаданої перевитрати.
- Рекомендація 40/30/20/10 — **тільки план поточного залишку**, вона не створює нові гроші й не змінює наявні правила розподілу конвертів.
- Дані залишаються у зашифрованому гаманці. У публічному коді немає транзакцій, імен чи номерів карток; публікація коду не синхронізує банкові рахунки.
- Для входу в **раніше створений** гаманець введи його первісну секретну фразу: старі фрази з менш ніж 12 символів тепер допускаються до криптографічної перевірки. Для **нового** гаманця мінімум 12 символів залишається обов’язковим. Оновлення не змінює ключ, пароль або зашифровані записи.

## Захищений хмарний акаунт (email + пароль + TOTP 2FA)

**Важливе розділення:** BMH Portal — окремий сервіс з власною серверною авторизацією. SOL Wallet **не використовує його базу паролів, сесії або замовлення**. Та сама модель MFA застосовується через **окремий проєкт Supabase Auth**. Немає справжньої 2FA у чисто локальному режимі: локально лише AES-256-GCM і секретна фраза.

1. Зроби резервну зашифровану копію чинного гаманця, не завантажуй її у GitHub.
2. Підготуй **окремий** Supabase-проєкт для приватного SOL Wallet; підтвердь email власника, перевір доступність TOTP MFA у Auth. У додаток можна вводити лише **public publishable/anon key**, ніколи secret/service_role.
3. У «Дані та безпека» задай URL і public key власного Supabase-проєкту. Після оновлення сторінки натисни «🛡️ Мій акаунт: email · пароль · 2FA» й створи або відкрий обліковий запис.
4. Після підтвердження email введи пароль, скануй новий SOL Wallet QR код у своєму Authenticator й введи 6 цифр. Це **окремий** TOTP-фактор, код BMH Portal не підходить.
5. Тільки після успішної перевірки кодом доступ до хмарних даних стає рівня AAL2. Після цього застосуй файл supabase/sol_wallets_mfa.sql у SQL Editor саме цього проєкту, забезпечивши RLS для власника і підписаного AAL2. Перевір анонімний, AAL1, AAL2 і cross-user сценарії до синхронізації.
6. Увійди до хмарного акаунта та підтверди завантаження **лише зашифрованої** копії. Не підтверджуй перезапис іншого гаманця до ручної перевірки версій. Зберігай власну офлайн зашифровану резервну копію.
7. При наступному хмарному вході: email + пароль → код Authenticator → власна секретна фраза гаманця. Три різні рівні: обліковий запис, другий фактор, розшифрування вмісту.

**Статус і обмеження:** frontend MFA реалізовано, але серверний акаунт і RLS у приватному проєкті не можуть бути увімкнені самою публікацією на GitHub Pages. Не називай 2FA «налаштованою», доки сервер, SQL-політика й QR-реєстрація не підтверджені практично. Локальний гаманець, захищений лише секретною фразою, залишається доступним, щоб не втратити старі фінансові записи. Паролі, QR-secret, токени та OTP не надсилай у чат і не додавай до публічного GitHub.

Для тестів: node --test tests/*.test.cjs; контроль CSP: node scripts/rebuild-csp.cjs після кожної зміни вбудованого JavaScript.
